# TradingView 警报消息填写

结论：不要填写自由文本。请在 TradingView 的“消息”框里填写固定中文 JSON。

你每天早上 10 点前先在 TV 上把当天关键位置警报设置好。价格行为触发后，TV 把这个 JSON 发给本 Agent；Agent 先发候选提醒，再等待二次判断是否给出正式 Taker 预警或方案。

## 固定字段

- `密钥`：填你的 Webhook 密钥。文档里只写 `<WEBHOOK_SECRET>` 占位。
- `品种`：建议用 `{{ticker}}`。
- `交易所`：建议用 `{{exchange}}`。
- `周期`：建议用 `{{interval}}`。
- `信号`：只允许 `突破确认`、`假突破`、`假跌破`、`流动性猎杀反转`、`2B反转`。
- `方向`：只允许 `做多` 或 `做空`。
- `价格`：必须用可解析数字，建议 `{{close}}`。
- `时间`：建议 `{{time}}`。
- `计划ID`：你早上给这个警报的唯一编号，例如 `BTC-20260705-R1`。同一 `计划ID + 信号 + 方向 + 周期` 会被视为同一个候选，重复触发会被抑制。
- `位置名称`：例如 `62500压力区`、`59700支撑区`。
- `关键位`：最核心价格，例如 `62500`。
- `区间下沿` / `区间上沿`：关键区间边界。
- `失效参考`：触发后若价格到哪里，说明这个候选失效。
- `触发场景`：一句话写清楚你早上预设的情景。
- `备注`：只写价格行为本质，不写交易结论。

## 推荐通用模板

```json
{
  "密钥": "<WEBHOOK_SECRET>",
  "品种": "{{ticker}}",
  "交易所": "{{exchange}}",
  "周期": "{{interval}}",
  "信号": "2B反转",
  "方向": "做空",
  "价格": "{{close}}",
  "时间": "{{time}}",
  "计划ID": "BTC-20260705-R1",
  "位置名称": "62500压力区",
  "关键位": "62500",
  "区间下沿": "62000",
  "区间上沿": "62500",
  "失效参考": "15m站稳62650",
  "触发场景": "上破压力区失败并跌回区间",
  "备注": "上破前高失败并跌回关键位"
}
```

## 信号备注写法

突破确认：

```json
"信号": "突破确认",
"方向": "做多",
"备注": "突破关键压力并收盘确认"
```

假突破：

```json
"信号": "假突破",
"方向": "做空",
"备注": "扫上方关键位后跌回区间"
```

假跌破：

```json
"信号": "假跌破",
"方向": "做多",
"备注": "扫下方关键位后收回区间"
```

流动性猎杀反转：

```json
"信号": "流动性猎杀反转",
"方向": "做多",
"备注": "扫下方流动性后快速收回"
```

2B反转：

```json
"信号": "2B反转",
"方向": "做空",
"备注": "上破前高失败并跌回关键位"
```

## 早盘设置原则

- 一个关键位置设置一个警报，不要把多个位置混在一条警报里。
- `计划ID` 必须唯一，便于后续去重和复盘。
- 缺少计划ID、关键位、区间、失效参考或触发场景时，只记录降级候选，默认不进入正式预警。
- 15m 以下的 2B 不进入正式预警。
- 备注只写触发事实，正式方向、入场、止损、TP 由二次判断给出。
