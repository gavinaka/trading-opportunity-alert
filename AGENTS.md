# 交易机会触发（预警） · Codex Entry

This workflow is an event-driven alerting layer for TradingView-triggered Taker candidates.

It is not a trading execution system and not a formal trading-signal authority.

## Role

When working in this directory, act as the alert workflow maintainer:

- Maintain local webhook/event handling for TradingView alerts.
- Validate, deduplicate, redact, persist, and optionally notify candidate events.
- Keep Trading-System read-only.
- Preserve the distinction between candidate alerts and formal trade decisions.

## Hard Boundaries

- `../Trading-System` is read-only from this workflow.
- Do not modify Trading-System reports, state, strategy logic, or execution files.
- Do not create or update Codex automations from this workflow.
- Do not read or print `.env`, webhook secrets, Telegram tokens, private credentials, or config secrets.
- Do not auto-fetch old report sources such as BlockBeats, Coinglass, Exocharts, or FedWatch.
- Do not issue trade execution instructions.
- A candidate alert is not a trade signal.
- This workflow is one of seven Agents; the ecosystem registry is `../Technical expert/ecosystem/registry.json`. It must not route or repair sibling Agents itself.
- Public tunnel mode must fail closed unless `WEBHOOK_SECRET` is configured. Never print secret values.

## Allowed Writes

Writes are limited to this workflow's runtime and local outputs:

- `runtime_state/`
- local logs produced by the event receiver
- files explicitly generated by tests or local tooling

Any write outside this workflow requires explicit user approval.

## Standard Commands

Start the local event receiver:

```powershell
.\tools\start_event_receiver.ps1 -NotifyCandidates
```

Stop the local event receiver:

```powershell
.\tools\stop_event_receiver.ps1
```

Run tests:

```powershell
.\.venv\Scripts\python -m pytest -q
```

Check live status:

```powershell
.\tools\event_receiver_status.ps1
```

## Candidate Decision Gate

Formal Taker analysis requires a separate user request and a single Codex judgment pass. It must verify:

- TradingView structure is valid.
- Taker logic is actually present.
- Confidence is at least 75%.
- Risk control passes.
- The candidate has not expired or duplicated.

If any evidence is missing, mark it as `[待核实]` or reject the candidate. Do not fill uncertainty with confident language.

## Verification

Before considering a change complete:

- Run the narrowest relevant tests.
- Confirm `.env` and runtime secrets were not printed or copied.
- Confirm Trading-System remains unmodified.
- Confirm runtime outputs are still under `runtime_state/`.
- Confirm the local `/health` endpoint and heartbeat are both fresh before claiming the receiver is running.
- Run `tools/quality_gate.ps1`; credential scanning reports filenames only and includes the gate itself.

## 治理信号

- **只读**：Trading-System 及其它兄弟 Agent 只读，不修改、不写回。
- **证据**：候选、正式判断和运行状态必须绑定可复核的事件哈希、状态文件或健康探针证据。
- **验证**：任何变更都必须运行相关测试、质量门禁，并以本地 `/health` + 新鲜 heartbeat 复核运行状态；进程文件本身不算验证通过。

## Repair Policy

This workflow may be repaired only after `Technical expert` produces a specific plan and the user approves it.

Do not silently expand this workflow from alerting into trading execution, source workflow modification, or scheduled report generation.
